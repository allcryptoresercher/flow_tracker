# Flow Tracker

Отдельный бот, который следит за спотовым потоком выбранной монеты на выбранной бирже и пишет в Telegram, когда режим потока меняется: начались продажи или начались покупки.

Наблюдение — это пара «монета + биржа». Оно живёт, пока его не удалят. Депозиты бот сам не ищет. Размер депозита можно указать вручную: в расширенном режиме по нему считается оценка того, какая доля объёма продаж прошла по бирже с момента добавления. Это оценка по агрессивным сделкам, а не факт продажи конкретного депозита.

Сводный поток складывается из спотовых пар той же монеты на биржах, включённых локально. Если биржа наблюдения и рынок в целом расходятся, сообщение это показывает.

Как из окна сделок получается текст уведомления, и как выглядят сообщения: [docs/messages.md](docs/messages.md).

## Что система делает

- Подписывается на публичные спотовые сделки только по монетам активных наблюдений.
- Копит минутные агрегаты и по ним оценивает режим на таймфреймах наблюдения.
- Шлёт сообщение при смене режима. В расширенном режиме дополнительно пишет о крупных сделках.
- По желанию дублирует начало продаж в Pushover.
- Отвечает только одному чату. Команды: `/track`, `/watches`, `/status`, `/untrack`, `/tf`, `/mute`, `/help`.

Вне задачи бота: поиск депозитов, on-chain данные, деривативы, стакан и торговля.

Дельта видит сторону агрессора. Продажа лимитным ордером или айсбергом проявляется с задержкой. На редких сделках короткие окна часто пустые, поэтому для таких монет уместнее длинные таймфреймы. Это же написано в `/help`.

## Состав

Python 3.11, asyncio, aiogram 3, ccxt, PostgreSQL 16, Redis 7, Docker Compose.

Контейнер приложения читает локальный `config.yaml` с диска. Секреты и пароли читаются из локального `.env`. Оба файла в репозиторий не входят. Образ их не содержит: после смены порогов достаточно поправить файл на сервере и перезапустить контейнер, пересобирать образ не нужно.

## Локальные файлы

| Файл | Назначение |
| --- | --- |
| `.env` | Токен бота, id чата, ключи Pushover, пароль базы, часовой пояс. Создаётся из `.env.example`. |
| `config.yaml` | Список бирж, пороги режима, параметры крупных сделок, переопределения по монете. Создаётся из `config.example.yaml`. |

`.env.example` и `config.example.yaml` содержат имена параметров, а не рабочие значения. Пороги в эти файлы не записывайте и в коммит не добавляйте.

Репозиторий: https://github.com/allcryptoresercher/flow_tracker

Команды ниже выполняются в каталоге проекта. Перед коммитом проверьте, что в индекс не попали `.env`, `config.yaml` и техническое задание с рабочими порогами, если оно лежит рядом.

```powershell
git init
git add .
git status
git commit -m "Initial Flow Tracker"
git branch -M main
git remote add origin https://github.com/allcryptoresercher/flow_tracker.git
git push -u origin main
```

`git status` перед коммитом не должен показывать `.env` и `config.yaml`. Если показывает — их подхватил не `.gitignore`, а старый индекс: уберите их из индекса и не коммитьте.

Дальше обычный цикл: `git add` изменённых файлов кода и документации, коммит, `git push`.

## Развёртывание на сервере

Нужны Docker и Docker Compose, исходящий доступ к Telegram, биржам и, если нужен Pushover, к `api.pushover.net`. Рядом может работать другой сборщик сделок: у этого проекта свои Postgres, Redis и свой набор подписок.

1. Поставьте Docker Engine и плагин Compose. На Ubuntu это пакеты `docker.io` и `docker-compose-v2` либо установка с сайта Docker. Пользователь, который запускает compose, должен быть в группе `docker`.

2. Склонируйте репозиторий и перейдите в него:

```bash
git clone https://github.com/allcryptoresercher/flow_tracker.git
cd flow_tracker
```

3. Создайте `.env` из примера и заполните его. `DATABASE_URL` должен использовать те же имя пользователя, пароль и имя базы, что `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB`. Хост в URL — `postgres`, порт `5432`: так контейнер приложения видит базу внутри compose-сети. `ALLOWED_CHAT_ID` — числовой id чата, которому бот отвечает. `TZ` — часовой пояс часов в сообщениях, например `Europe/Vienna`.

```bash
cp .env.example .env
```

4. Создайте `config.yaml` из примера. В `exchanges.enabled` перечислите id бирж, с которых можно читать спот: `binance`, `bybit`, `bitget`, `okx`, `htx`, `kucoin`, `mexc`, `gate`, `bingx`, `hyperliquid`, `coinbase`, `lbank`. Пороги режима и крупных сделок допишите в этот же файл, если запасных значений в коде недостаточно. Файл остаётся только на сервере.

```bash
cp config.example.yaml config.yaml
```

5. Соберите и запустите:

```bash
docker compose up -d --build
```

При старте контейнер дожидается Postgres, применяет миграции и поднимает бота. Схема также создаётся при запуске приложения, если миграция не прошла.

6. Проверьте, что контейнеры в состоянии running и в логах приложения нет ошибки токена или конфига:

```bash
docker compose ps
docker compose logs -f app
```

В Telegram отправьте боту `/help` из разрешённого чата. Чужим чатам бот не отвечает.

Обновление кода:

```bash
git pull
docker compose up -d --build
```

Смена порогов или списка бирж: правьте `config.yaml` на сервере и перезапустите только приложение, без пересборки:

```bash
docker compose restart app
```

Остановка: `docker compose down`. Том `pgdata` при этом сохраняется, наблюдения не пропадают. `docker compose down -v` удаляет том базы вместе с наблюдениями.

Логи ограничены по размеру настройкой драйвера в `docker-compose.yml`. Ошибки бирж, в том числе ответы 429, пишутся в лог приложения. В чат уходит только пропажа потока дольше порога из конфига и последующее восстановление.
